# 晨的助手 v0.3.3

个人长期使用的 PWA 工作助手。当前以**客户业务台账 + 连续缴费作业 + 优惠管理 + 客户资料导入导出**为核心，目标是减少重复维护、降低遗漏，并让每个月的缴费流程可以连续执行、可回退、可追踪。

## 当前核心能力

- 客户工作区：缴费、业务、优惠、联系人、待办、跟进统一围绕同一份客户/业务主数据工作。
- 高密度缴费：号码、账号、金额、核对状态集中在单行完成，适合大量业务连续查询和录入。
- 四阶段缴费闭环：`金额核对 → 通知客户 → 发起缴费 → 完成缴费`。
- 行级核对：固定金额通常自动确认；变动金额需要人工确认；固定金额若被手动改动，该行也会重新进入待核对。
- 安全回退：任何真实金额改动都会使依赖旧金额的后续流程自动失效，但不会清掉其他未改动行的核对状态。
- 完成缴费后仍可修正金额：系统先恢复缴费前保存的周期状态，再回退本次流程，避免多月周期被错误推进。
- 客户通知与邮件：支持生成缴费图片；缴费邮件模板按客户完全隔离；Windows 本地 Foxmail 助手通过原生 MAPI 在创建写信窗口时直接附带 TXT 文件。
- Excel 客户交换：支持一客户一工作表的模板、导入预览、确认导入和完整导出。
- 优惠管理：优惠与具体业务关联，支持到期提醒、编辑、结束和续约历史。
- 业务展示：业务列、缴费列可按客户配置，顺序输入采用“插入位置”逻辑。

## 四阶段缴费流程

### 1. 金额核对

系统以每一条本月应缴业务的核对状态为真实依据：

- 固定金额未发生人工修改时自动确认。
- 变动金额每月需要人工确认。
- 固定金额一旦手动改动，只把这一条改成待核对；确认一次后恢复为正常固定金额状态。
- 当本月所有应缴行均已确认时，第 1 阶段自动完成，不需要再额外点击一次“金额核对”。

金额输入仍保持连续作业习惯：单击进入/全选，输入后按 Enter 保存，并继续处理下一条需要核对的数据。

### 2. 通知客户

金额全部核对后进入客户通知阶段。第一次点击准备本次缴费内容/图片，实际发送后再次点击“通知客户”即可进入下一阶段。该环节不再使用阻塞式确认弹窗，避免打断连续操作。

### 3. 发起缴费

通知客户后，可以按**当前客户独立保存**的缴费邮件模板准备邮件。收件人、主题、正文和 TXT 附件文件名不会从其他客户或全局配置自动继承；缺少必填项时只提示补充。

Windows Foxmail 助手采用原生 Simple MAPI 创建写信窗口，TXT 作为邮件创建参数直接传给 Foxmail，不再依赖剪贴板 `Ctrl+V` 粘贴附件。实际发送后再次点击“发起缴费”即可进入下一阶段，同样没有确认弹窗。

### 4. 完成缴费

实际完成支付后确认“完成缴费”。多月周期业务会推进下一次应缴月份，同时保存本次流程所依赖的缴费前周期快照。

如果完成后发现金额有误，仍可直接修改。系统会自动恢复快照、撤回后续阶段，并只让被修改的那一行重新核对，全程不弹出金额回退确认框。

## 缴费工作区

当前工作区仍采用高密度单行展示，核心交互包括：

- 号码、账号可快速复制。
- 金额可直接编辑，Enter 保存。
- 每行 `○ / ✓` 显示核对状态。
- 顶部显示待核对数量，避免漏查。
- 固定/变动金额规则与具体月份的缴费记录分开保存。
- 0 元表示本月已确认但无需实际缴费，生成 TXT 时自动排除。
- 缴费展示字段可配置，业务展示字段也可按客户独立配置。

## Excel 客户导入 / 导出

v0.3.2 起使用“一客户一工作表”的 Excel 交换格式，格式标记为：

```text
晨的助手客户档案 v0.3.2
```

每个客户工作表可以承载客户基础资料，以及业务、开票组、联系人、优惠、待办、拜访/跟进、金额规则、历史缴费记录和缴费流程记录等数据。

推荐流程：

```text
下载模板 / 导出现有数据
        ↓
在 Excel 中整理
        ↓
上传并预览
        ↓
确认无误后正式导入
```

导入采用“先预览、再确认”的两阶段方式，避免上传后立即写入数据库。完整导出可作为迁移、备份和批量整理的辅助方式；正式数据库备份仍应以 SQLite 备份为准。

## 业务与优惠

业务是号码/账号等信息的唯一主数据来源，缴费和优惠只是围绕业务形成不同工作视图，不重复维护三份号码。

优惠直接关联业务。修改业务侧优惠信息后会同步到优惠视图；优惠名称支持快速复制和就地编辑。续约保留旧优惠周期并新建下一周期，不覆盖历史。

## 主要数据模型

- `customers`：客户主档案及客户级偏好。
- `services`：业务/号码/账号唯一主数据，以及缴费周期等长期属性。
- `payment_entries`：某业务某个月的金额、参考金额、来源与核对状态。
- `service_payment_rules`：固定/变动金额规则及其生效月份。
- `customer_payment_runs`：客户某个月四阶段缴费流程的状态与时间记录。
- `customer_mail_templates_v03`：每个客户独立的缴费邮件收件人、主题、正文和 TXT 附件文件名。
- `promotions`：与业务关联的优惠周期及历史。
- 运行时状态/快照：用于延期、本月不缴、完成缴费后的安全回退等场景。

## 日期与缴费周期

客户工作区的日期继续使用手工输入格式：

```text
1900/07/07
```

缴费周期以月数为核心，例如：

```text
1
3
6
12
```

系统结合周期、下次应缴月份和运行时状态判断本月是否进入缴费工作台；已经进入本月流程的数据不会因为后续周期推进而在本月操作中突然消失。

## 缴费 TXT

当本月所有需要核对的业务均已确认后，可生成正式 TXT：

```text
号码|金额
```

0 元自动排除，不添加标题、合计或说明。手工下载 TXT 与 Foxmail 附件共用同一个生成函数，避免两条链路内容不一致。

## 部署

服务器端更新：

```bash
cd /opt/chen-assistant
./deploy.sh
```

部署脚本负责拉取 `main`、备份 SQLite 数据库、安装依赖、执行语法/路由/模板检查、数据库迁移、重启服务并检查 `/health`。

当前应用版本可通过 `/health` 或页面品牌信息确认，应显示 `0.3.3`。
