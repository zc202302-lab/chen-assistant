# 晨的助手 v0.2.1

个人长期使用的 PWA 工作助手。客户管理以**缴费作业**为第一核心场景。

## 客户模块结构

客户首页不再把所有功能堆在一个长页面里，而是作为入口：

- 缴费
- 业务
- 联系人
- 待办
- 跟进

每个模块进入独立二级页面。

## 缴费工作区

缴费页使用高密度单行模式，适合一个客户几十到上百项业务连续操作。

每行主要展示：

`业务属性 | 号码 | 账号 | 金额 | 固定/变动 | 核对状态`

操作方式：

- 单击号码：复制号码。
- 单击账号：复制账号。
- 双击业务属性、号码或账号：打开快速编辑，修改类型、姓名/属性、号码、账号。
- 单击金额：自动全选当前金额。
- 金额不变：直接按 Enter。
- 金额变化：输入新金额后按 Enter。
- 本月不缴：输入 `0` 后按 Enter。
- Enter 保存后自动寻找下一条待核对业务。
- 默认只显示“待核对”；可切换全部、金额异动、0元。
- 每条业务可直接在“固定 / 变动”之间切换。
- 固定金额业务自动确认；取消固定后，本月重新进入待核对。
- 所有变动业务核对完成后才能生成正式 TXT。
- TXT 只输出非 0 元项目，每行严格为 `号码|金额`。

## 金额与历史

- 新月份不清空金额，而是继承上一期金额。
- `payment_entries` 按“业务 + 月份”保存金额，并用 `confirmed` 独立记录本月是否核对。
- `service_payment_rules` 记录固定/变动规则及生效月份。
- 新增业务从当前月份生效；停用业务不删除历史。

## 部署

服务器目录：

```text
/opt/chen-assistant
```

正式版本更新：

```bash
cd /opt/chen-assistant
./deploy.sh
```

部署脚本会先备份 SQLite 数据库，再拉取 `main`、迁移数据库、重启服务并执行健康检查。

## 缓存策略

从 v0.2.1 开始，JS/CSS 使用版本化 URL，Service Worker 不再缓存应用脚本和样式，避免客户端继续运行旧交互代码。

## 安全边界

`.env`、`data/app.db`、`.venv/` 不上传 GitHub。个人网址密码仍是服务器端 Fernet 加密，不是零知识密码保险箱。
