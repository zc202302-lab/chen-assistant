# 晨的助手 v0.2.5

个人长期使用的 PWA 工作助手。客户管理当前以**连续、高频、低遗漏的缴费作业**为第一核心场景，并开始建立优惠续约闭环。

## 首页

首页采用横向标签：`待办 / 缴费 / 优惠到期 / 最近客户`。点击标签只切换下方对应内容，不把所有模块纵向堆在一页。

## 客户数据模型

v0.2.5 明确采用“一个业务主数据，多种关联记录”，而不是在缴费、业务、优惠三处重复维护号码：

- `services`：号码/账号唯一主数据，保存类型、姓名/属性、缴费周期、发票组等。
- `payment_entries`：某个业务某个月的金额、参考金额、是否核对。
- `service_payment_rules`：固定/变动金额规则及生效月份。
- `customer_payment_runs`：整个客户某个月的缴费流程状态。
- `promotions`：某个业务的一段优惠周期及续约历史。

因此界面上可以分别有“缴费 / 业务 / 优惠”三个工作区，但底层不会复制三份号码。

## 缴费工作区

高密度单行主要展示：`拖动 | 两个默认属性值 | 号码 | 账号 | 金额 + 核对状态 | 固/变`。

- 第一列不再重复显示“类型 / 姓名”等属性名称，只直接显示当前客户统一选择的两个属性值。
- 表头“属性 ⚙”一次设置这个客户所有行的默认显示属性。
- 单击号码/账号复制；单击金额全选；Enter 保存并进入下一条未核对金额。
- v0.2.5 移除了旧版脚本中的重复缴费事件处理，避免多套 Enter 逻辑同时执行导致乱跳。
- 每行 `○ / ✓` 加顶部“需核对 / 未核对”双保险。
- 固定金额自动确认，变动金额每月需人工确认；0 元代表本月已核对但无需缴费，并从 TXT 排除。

## 缴费周期自动判断

每项业务可设置：

- `payment_interval_months`：周期月数，例如 1 / 3 / 6 / 12。
- `next_payment_period`：下一次应缴月份，例如 `2026-10`。

规则：

- 周期 1 个月：每月自动进入缴费工作台。
- 多月周期：当前月份达到或超过“下次应缴月份”后进入工作台；即使逾期跨月也不会消失。
- 本月不应缴的业务只留在“业务”模块，不进入缴费工作台。
- 标记整个客户“已完成缴费”后，多月周期业务自动推进下一次应缴月份。

## 客户本月缴费闭环

金额核对和实际缴费彻底分开：

`正在核对金额 → 金额已核对、待通知客户 → 已通知客户、待缴费 → 已完成缴费`

其中“金额已核对”由所有应人工核对项目完成后自动得到；“已通知客户”和“已完成缴费”必须人工操作确认。

## 优惠 / 续约

优惠直接关联 `services` 中的一项业务，记录：优惠名称、开始日期、到期日期、提前提醒天数、状态和备注。

- 临期和已过期优惠进入关注范围。
- 续约时不直接覆盖旧到期日，而是把旧优惠标记“已续约”，同时创建新的优惠周期，因此可以保留历史。
- 可以明确结束某项不再续约的优惠。
- 首页“优惠到期”只显示仍需处理的有效优惠。

## 缴费 TXT

只有本月所有需要人工核对的变动业务都核对完成后才能生成正式 TXT。格式严格为：

```text
号码|金额
```

0 元自动排除，不添加标题、合计或说明。

## 部署

```bash
cd /opt/chen-assistant
./deploy.sh
```

部署脚本会自动备份 SQLite 数据库、拉取 GitHub `main`、安装依赖、执行数据库迁移、重启服务并检查 `/health`。

## 安全边界

`.env`、`data/app.db`、`.venv/` 不上传 GitHub。个人网址密码目前仍是服务器端 Fernet 加密，不是零知识密码保险箱。
