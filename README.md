# 晨的助手 v0.2.6

个人长期使用的 PWA 工作助手。客户管理以**连续、高频、低遗漏的缴费作业**为第一核心场景，同时建立业务总览与优惠续约闭环。

## 首页

首页采用横向标签：`待办 / 缴费 / 优惠 / 最近客户`。点击标签只切换下方对应内容。

优惠首页按工作行动窗口区分：

- `已经到期`：到期月份为下个月或更早，需要优先行动。
- `即将到期`：到期月份为下下月，需要提前准备。

## 数据模型

采用“一份业务主数据，多种关联记录”：

- `services`：号码/账号唯一主数据，保存类型、姓名/属性、缴费周期（月）、发票组等。
- `payment_entries`：某业务某个月的金额、参考金额、是否核对。
- `service_payment_rules`：固定/变动金额规则及生效月份。
- `customer_payment_runs`：整个客户某个月的缴费流程状态。
- `promotions`：某业务的一段优惠周期及续约历史。

缴费、业务、优惠是三个工作视图，但不会复制维护三份号码。

## 缴费工作区

高密度单行展示：`拖动 | 两个默认属性值 | 号码 | 账号 | 金额 + 核对状态 | 固/变`。

- 表头“属性 ⚙”一次设置这个客户所有行的两个默认显示属性。
- 单击号码/账号复制。
- 单击金额全选；Enter 保存并进入下一条未核对金额。
- 每行 `○ / ✓` 加顶部“需核对 / 未核对”形成双重防漏。
- `✓` 可点击撤销为 `○`；`○` 也可点击按当前金额恢复核对。
- 固定金额自动确认；变动金额每月需人工确认。
- 0 元表示本月已核对但无需缴费，并从 TXT 排除。

## 日期输入

v0.2.6 的客户工作区不再使用浏览器日期选择器。所有可编辑日期都手工输入，并严格使用：

```text
1900/07/07
```

系统内部仍规范化保存日期，以保证排序和自动判断可靠。

## 缴费周期

界面只保留**缴费周期（月）**这一项，直接输入整数，例如：

```text
1
3
6
12
```

不再维护“月 / 季度 / 半年 / 年”等自由文字。系统结合周期月数、上次缴费日期和下次应缴月份判断本月是否应缴；逾期项目不会跨月消失。

## 客户本月缴费闭环

`正在核对金额 → 金额已核对、待通知客户 → 已通知客户、待缴费 → 已完成缴费`

“金额核对”与“通知客户”“完成缴费”是不同状态。

## 业务总览

“业务”是客户全部业务信息的完整集合处。每条业务尽量直接展示：

- 类型、姓名/属性
- 号码、账号
- 缴费周期（月）
- 本月应缴/不缴
- 固定/变动金额
- 发票组、付款方式、发票类型
- 套餐
- 上次缴费、下次应缴
- 优惠状态与到期日
- 备注

并提供多维标签筛选：业务类型、本月缴费状态、金额规则、优惠状态、发票组。不同维度可以叠加筛选，一键清除。

## 优惠 / 续约

优惠直接关联业务号码。续约不覆盖旧记录，而是保留历史并创建下一优惠周期。

工作区按到期月份分组：`已经到期 / 即将到期 / 后续到期 / 历史`。

## 缴费 TXT

只有本月所有需要人工核对的变动业务都核对完成后才能生成正式 TXT：

```text
号码|金额
```

0 元自动排除，不添加标题、合计或说明。

## 部署

```bash
cd /opt/chen-assistant
./deploy.sh
```

部署脚本会自动备份 SQLite 数据库、拉取 GitHub `main`、安装依赖、检查 Python/路由/Jinja 模板、执行数据库迁移、重启服务并检查 `/health`。
