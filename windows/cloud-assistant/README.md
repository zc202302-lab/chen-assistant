# 云电脑集团成员助手

## 环境与边界

云电脑离线，程序放在 E 盘，例如 `E:\Assistants\CloudMemberAddAgent`。
本机共享目录 `E:\ChenBridge` 对应云电脑 `Y:\ChenBridge`。本机联网下载更新，云电脑只读取共享目录，不需要联网。
保留已经登录的业务页面及调试端口9222。控件检查失败时用 `diagnose_browser.cmd` 做只读诊断；不要求反复登录。

## 永久中转表

`号码加集团.xlsx` 不设表头。A列为5至20位数字号码，B列为集团搜索值，目前使用固定值。
保存并关闭Excel后运行助手。原文件不删除、不移动，结果保存后仅清空内容，保留有效空工作簿。
执行中不要覆盖中转表；新版会比较内容并在Windows句柄锁下清空，发现新内容或文件忙就保留。

## 执行与恢复

云电脑双击 `start_agent.cmd`。每行搜索集团、核对身份、检查成员列表，输入号码并等姓名加载，再选择集团通讯录并确认。
缺少唯一控件/集团身份时暂停。确认阶段异常或回执不确定时，必须先人工核对。

`journals`保存逐行状态：浏览器操作前写入执行中，确认结果后立即保存。突然退出后不会重跑执行中行，也不会自动继续剩余行。
结果写入`results`，快照写入`processing`、`processed`或`errors`。恢复记录损坏或无法保存时，保留中转内容并暂停；不要删除恢复记录来强制重试。
`--check-file`仅检查格式；`--check-browser`仅检查搜索控件；`--self-check`仅验证程序导入，均不提交成员。

文件锁与恢复记录只保证当前共享文件系统的协作进程；不构成不同同步副本间的分布式事务。真正的业务提交和页面分页仍需实机验收。

## 手动更新

本机双击已有的`ManualUpdate`，或运行`background_sync.ps1`生成此快捷方式。
一次检查结束后显示完成/失败提示，不注册Windows登录启动，不长期保持CMD。
需要登录GitHub CLI的账号留在本机，不放共享目录；首次认证和旧安装的引导器迁移不由本代码自动完成。

Python更新器是唯一同步实现，PowerShell与CMD只是入口。在线操作均为单次；云电脑在两批之间交由独立更新器更新和重新启动。
正常包从main稳定通道获取。PR构建包的版本文件明确标记development通道，只用于当前开发验证；可用`--channel stable`手动切换，不能把PR构建当正式发布。
更新包包含程序、配套脚本和版本文件。更新前保存整组备份和恢复标记，替换后只运行无业务自检；失败或中断回滚，不改中转表、结果、恢复日志或用户路径。
运行中的更新器不会覆盖自己；新更新器暂存为`CloudOfflineUpdater.next.exe`，下次由入口脚本替换。
协议1旧引导器不具备自更新能力：升级到协议2的引导器需要一次安装迁移，不能声称旧安装已自动获得全部治理。
SHA256只验证传输完整性，不能替代发布签名或共享目录写权限控制；更新签名尚未实现。

## 代码职责

- `member_add_agent.py`：CLI与批次编排。
- `task_journal.py`：逐行持久化、原子结果、批次互斥。
- `member_models.py`：任务与异常类型。
- `member_workbook.py`：有大小/展开/行数上限的表格解析。
- `member_browser.py`：CDP连接和已知刷新弹窗。
- `member_page.py`：页面探针。
- `member_flow.py`：一条成员操作、身份与回执核对。
- `relay_store.py`：永久文件租约与比较清空。
- `offline_update.py`：更新通道、单次同步、整组回滚及导入自检。

所有测试在临时目录与模拟浏览器中运行，不提交真实号码。Windows CI另外验证真实文件分享锁、EXE构建与无业务自检。
