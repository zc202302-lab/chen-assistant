# 晨的小助手 · 长期产品要求

本文件只保存相对稳定、跨版本长期有效的产品边界。当前开发进度不要写在这里，应写入 AI_HANDOFF。

## 稳定业务基线

以下模块属于稳定基线，新开发不得破坏：

- 客户管理
- 缴费
- 客户资料
- 导入
- 远程存储
- Windows 助手成熟功能

客户实例数据必须归属于明确客户，不得因模板、缓存或共用页面造成串客户。

## Windows 助手

- Windows 端统一由 `win-assistants` 维护。
- 短信、Foxmail、久坐等已纳入同一发布包。
- 用户侧只保留一个统一“检查更新”入口。
- 任一内置模块更新时，更新整个 `win-assistants.exe`，不再为久坐等模块保留独立 Git 更新链。
- Foxmail / 缴费等既有安全边界必须保留；涉及草稿、剪贴板或文件的流程不得擅自扩展为自动发送。

## 号码收集 / Windows 提醒

- Windows 提醒中的每条号码必须提供“已完成”，成功后同步 Web 后台状态为已处理；不能只在本机隐藏。
- Web 后台若先完成某条号码，Windows 下一次同步后不得再次把该号码作为未完成提醒。
- 新号码仍即时提醒；提醒窗口允许直接关闭，关闭不等于完成，未完成号码在后续设定时间继续提醒。
- 每日定时提醒由 Windows 端本地配置，最多 5 个时间点；默认可使用 09:00、16:00，用户可自行修改或清空。
- 批量处理的长期方向：Web 端保存用户上传的 Excel 模板；Windows 端可配置本地输出目录；点击批量处理后，把待处理号码按模板规则生成固定格式文件并保存到指定目录。
- 批量处理模板的字段、工作表、单元格映射、覆盖/追加规则尚未确定，在用户后续详细定义前不得自行猜测或固化转换逻辑。

## 久坐模块

- 作为 win-assistants 内置模块维护，而不是独立用户侧产品。
- 保留成熟的人体存在检测、多区域、RTSP、强制休息、统计和本地配置/数据能力。
- 只在明显离开座位时计为休息，不能因静止、靠椅等轻易误判。
- 有效离开达到强制休息时间后应视为完成休息并清零工作累计。
- 正式产品不应依赖第二套托盘和第二套独立更新入口。

## 开发阶段边界

- 若当前阶段是代码治理，不顺手增加新用户功能、新 UI、新数据库结构或新业务规则。
- 若当前阶段是产品开发，沿现有产品主线继续，不重新设计已经确定的整体架构。
- 新需求若会改变稳定业务规则，必须先通过实际代码、测试和文档同步完成，而不能只存在聊天记录中。
