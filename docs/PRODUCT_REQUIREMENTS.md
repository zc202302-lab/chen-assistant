# 晨的小助手 · 长期产品要求

本文件只保存相对稳定、跨版本长期有效的产品边界。当前开发进度不要写在这里，应写入 AI_HANDOFF。

## 平台固定称呼

必须遵守[网站、手机和电脑客户端固定术语](TERMINOLOGY.md)。网站仅管理提醒；接收端只有手机和电脑客户端。界面和说明明确写平台名称，不使用“本机”“当前设备”等模糊指代。

## 页面总体设计原则：分层展示

用户于2026-10-06明确要求：打开页面应能一眼看清功能分类；分层次，不要把所有信息平铺在一个页面上。适用于全部新页面及现有页面改造。

- 采用“功能分类 → 当前任务 → 具体内容/操作”的层次。入口页优先回答有哪些功能、当前在哪一类、下一步点哪里。
- 同一页面只突出当前主要任务。浏览列表、创建、导入、设置、归档等不同任务通过清晰的二级导航、独立页面或按需打开的面板组织。
- 默认展示常用分类及当前分类所需的信息；完整表单、详细说明、低频设置在用户主动进入对应任务后展示。
- 分类、内容、操作在视觉和结构上区分，保持明确标题、选中状态与返回路径。分类名称使用用户熟悉的业务词，不堆叠同级按钮和说明。
- 分层不能牺牲当前任务效率：同一任务必要的数据和操作保留在一起，成熟缴费工作台的连续录入、复制和核对体验保持。
- 桌面和手机均应在首屏看清主要功能分类与主要操作；以实际页面交互验收，不能只靠增加卡片、缩小字体或留白判定完成。

清单页面：默认“我的清单”，搜索与列表归入该视图；“新建清单”和“已归档”提供明确入口，Excel导入归入“新建清单”菜单。完整新建表格进入新建任务后展示，不常驻清单首页。

## 保存后的数据刷新

- 此原则适用于全站。保存成功后及时同步相关数据，按影响范围更新字段、行、统计或列表，尽可能保留当前标签、焦点、滚动位置与未提交的编辑。普通数据保存优先局部刷新，需要导航或重建界面结构的操作沿用相应页面流程。
- 缴费资格变化应同步影响缴费清单、应缴计数、金额合计、流程与客户管理看板。

## 稳定业务基线

以下模块属于稳定基线，新开发不得破坏：

- 客户管理
- 缴费
- 客户资料
- 导入
- 远程存储
- Windows 助手成熟功能

客户实例数据必须归属于明确客户，不得因模板、缓存或共用页面造成串客户。

## Windows 助手

- 主窗口采用顶部导航分模块展示；日常页只突出当前模块状态和操作。全局设置仅保留开机启动、旧工具接管、版本及统一检查更新等客户端设置；模块启停/配置归所属模块的“模块设置”折叠面板，再进入既有详细设置。切换导航不停止后台模块；小窗口可访问设置，检查更新时显示实际进度。

- Windows 端统一由 `win-assistants` 维护。
- 短信、Foxmail、久坐等已纳入同一发布包。
- 用户侧只保留一个统一“检查更新”入口。
- 任一内置模块更新时，更新整个 `win-assistants.exe`，不再为久坐等模块保留独立 Git 更新链。
- Foxmail / 缴费等既有安全边界必须保留；涉及草稿、剪贴板或文件的流程不得擅自扩展为自动发送。

## 号码收集 / Windows 提醒

- Windows 提醒中的每条号码必须提供“已完成”，成功后同步 Web 后台状态为已处理；不能只在电脑客户端隐藏。
- Web 后台若先完成某条号码，Windows 下一次同步后不得再次把该号码作为未完成提醒。
- 新号码是否即时提醒由手机或电脑客户端各自的规则决定；提醒窗口允许直接关闭，关闭不等于完成，未完成号码可在后续设定时间继续提醒。
- 手机/Web Push规则由网页设置保存，手机接收提醒具有独立开关；关闭手机接收不改变Windows是否开启提醒，网页总开关关闭则两端均暂停；Windows客户端的即时/定时、通知类别、时间点、每天/指定星期规则在客户端单独配置并保存到电脑客户端。网站中的电脑提醒开关与通知总开关共同控制Windows接收，接口仍仅下发是否开启提醒，不得覆盖电脑客户端的方式、类别、时间及循环。客户端也可本地暂停提醒；任一总开关关闭均不提醒。即时和定时可单选或全选，定时最多12个北京时间点，支持每天或每周任选日期；升级保留既有本地时间。
- 未加号码、待办分别可选；待办可选择全局待办、客户待办。已完成/改变提醒时间的任务不再发送旧提醒，待办已读不等于完成。设备接收开关独立于账号总开关，测试通知不受业务类别开关影响但受总开关控制。
- 批量处理的长期方向：Web 端保存用户上传的 Excel 模板；Windows 端可配置本地输出目录；点击批量处理后，把待处理号码按模板规则生成固定格式文件并保存到指定目录。
- 批量处理模板的字段、工作表、单元格映射、覆盖/追加规则尚未确定，在用户后续详细定义前不得自行猜测或固化转换逻辑。

## 久坐模块

- 作为 win-assistants 内置模块维护，而不是独立用户侧产品。
- 保留成熟的人体存在检测、多区域、RTSP、强制休息、统计和本地配置/数据能力。
- 只在明显离开座位时计为休息，不能因静止、靠椅等轻易误判。
- 有效离开达到强制休息时间后应视为完成休息并清零工作累计。
- 正式产品不应依赖第二套托盘和第二套独立更新入口。

## 开发阶段边界

- 若当前阶段是代码治理，不顺手增加新用户功能、新 UI、新数据库结构或新业务规则。
- 若当前阶段是产品开发，沿现有产品主线继续，不重新设计已经确定的整体架构。
- 新需求若会改变稳定业务规则，必须先通过实际代码、测试和文档同步完成，而不能只存在聊天记录中。


## 清单网页表格（2026-10-06）

- 新建清单默认4个数据行、3列，可直接编辑标题行和单元格；支持逐列筛选、增行增列、拖动行高列宽及Excel多格粘贴。
- Excel导入属于“新建清单”菜单，不作为清单首页独立分类。保留原导入校验和预览确认；新建导入不提供范围选择，自动读取所选工作表从A1到全部有效内容（含带格式空白单元格和合并区域）的范围；超限明确报错而不截断。显示Excel范围的字体、填色、边框、合并区域、对齐、数字格式和行列尺寸，导出真实XLSX并还原表格格式。
- 既有清单记录、关联客户、状态、备注、隐藏字段保留；详情和字段设置按需展开。整表保存应事务化，并拒绝覆盖其他窗口已更新的记录。
- 页面删除纯介绍、产品背景和实现机制等冗余说明；必填、错误、状态、操作约束及会改变用户操作结果的信息继续保留。



## 工作入口和号码归档（2026-10-08）

- 工作空间划分“常用入口”和“辅助入口”；所有模块入口使用相同尺寸小方块。编辑模式支持拖动排序、跨区域移动、取消和保存；布局存到服务端，刷新/换浏览器保持。保留全部既有入口和业务路由。
- 前进/后退箭头置于顶部栏左侧提醒后方；主区域导航仍居中，搜索在右侧，桌面/手机无重叠。
- 号码收集的未加列表下增加“已录号码”，默认折叠，仅显示数量；展开查看号码和录入时间。手动“已录入”和Windows完成操作均进入同一已录列表。
- 电脑客户端批量Excel原子写入成功后，通过客户端签名成功回执将本批次快照ID标记已录；失败/未知结果不能标记，批次准备时不标记，期间新提交号码保持未加。
- Windows持久化成功回执并自动重试状态同步；浏览器可同步同一回执，重复回执不能延长保留期或重复写入Excel。旧客户端无成功回执协议时要求统一升级0.5.13；已有单条完成接口保持兼容。
- 已录号码以完成时间保留5天，到期后台自动清理，页面读取亦清理；未加号码不得按此规则删除。后台清理独立于可选手机推送能力。


## 优惠编号与全量优惠（2026-10-10）

- 每个优惠的到期时间（含业务属性弹窗中的关联优惠）采用自由文本，数字与“/”均可手动输入、删除、修改；保存不补零、不自动加斜杠、不强制日期格式。完整有效数字日期用于原到期分组，其余文本保留在全量表格。
- 业务关联优惠左侧编号可编辑，1～5对应固定优惠列，允许缺号、不从1开始；保存后按编号升序排列。同一业务的有效优惠编号不能重复。
- 优惠页底部增加默认折叠的全量优惠，紧凑表格、首行为标题，列为号码、优惠1、到期时间……优惠5、到期时间，共11列。只显示有关联有效优惠的业务，行序与业务模块一致；缺号对应两格空白。所有列等宽、文字居中、固定紧凑行高，超宽内容单行截断，原始值与Excel不删减。
- 全量表格号码和续约行动区号码双击打开该条业务统一属性编辑器，保存后全局使用最新数据。优惠名称单击复制并弹出完整内容，再点原名称或其他位置收起；保留原双击改名。
- 下载真实Excel，标题、行序、格内文本、空格与表格共用相同投影，不额外添加客户名称、备注、统计等列。号码和时间写为文本，保留长号码、前导零和自由输入。


## 缴费模式与完成条件（2026-11-05）

- 业务属性顶部使用“缴费模式”，选项为“周期缴费”“指定缴费”。周期缴费按上次缴费时间加缴费周期（月）计算下次日期，月末自动取目标月份最后一天；指定缴费优先按用户填写的下次缴费时间判定是否进入缴费页面。进入缴费页面仍按目标月份1日起，逾期不消失。
- 原周期业务切换为指定缴费且尚未到触发月份时，保存后自动从当期缴费清单和准备记录移出。
- 新增业务默认上次缴费时间为创建当天，缴费周期为1个月，默认周期缴费；用户填写的历史值、导入数据不批量重置。完成缴费更新上次日期为当天；指定缴费保留新设置的下次日期，周期缴费自动计算。
- 点击完成缴费时，仍启用且为指定缴费的业务必须逐条处理。显示“请设置下次缴费时间”及尚需处理的业务数量，按钮为“进入”“取消”。进入后打开第一条业务属性，保存后继续下一条；日期须与开始本次处理前不同，仅改变日期格式不算修改。
- 用户补充：指定缴费改为周期缴费，或者关闭业务，同样解除该条日期限制。未处理完的其他指定缴费业务仍阻止完成；全部关闭或全部转换后允许完成。关闭业务不更新缴费日期。
- 准备过程按客户、缴费月份持久化，刷新可继续。在完成缴费流程中为当期已纳入办理的指定业务安排未来日期时，保留本次待完成记录。取消不标记完成。服务端同样校验，缓存旧页面或直接请求不能绕过。撤回完成恢复本次处理前日期。
