# 晨的助手：工作模块业务架构

## 目标

工作模块从 v1.4 起固定为两个用户可见的一层模块：

1. **客户管理**：围绕具体客户组织日常工作。
2. **工作资料**：管理跨客户复用的工作知识、文件和操作资料。

系统内部另外保留一个不作为一级业务模块展示的 **公共模板 / 规则层**。它负责定义结构、默认值和规则，但不拥有客户实际业务数据。

---

## 一、客户管理

客户管理由一个个客户工作空间组成。任何客户实例数据都必须能明确回答“它属于哪个 customer_id”。

典型客户实例数据包括：

- 客户基础信息；
- 客户业务实例；
- 缴费数据和缴费流程状态；
- 联系人；
- 客户资料（营业执照、合同、报价单、项目方案、现场照片等）；
- 待办和跟进；
- 客户个性化属性及展示配置。

### 客户之间的关系

**数据独立，规则可共享。**

例如：

- A 客户和 B 客户都可以使用“互联网专线”业务模板；
- 但 A 客户的带宽、月费、IP 数量、合同日期等实际值只属于 A 客户；
- 修改公共模板不能覆盖已经存在的客户实例值。

---

## 二、工作资料

工作资料不是客户附件库，也不是普通网盘。它是可跨客户复用的工作知识库。

首批固定分类：

- 产品资料；
- 资费资料；
- 开通流程；
- 操作指南；
- 系统截图；
- 制度规范；
- 模板文件；
- 其他资料。

### 资料未来的基础数据结构

一条工作资料至少预留以下概念：

- 标题；
- 分类；
- 关联产品；
- 版本；
- 生效日期 / 失效日期；
- 状态（有效、待更新、已失效、归档）；
- 标签；
- 正文内容；
- 附件；
- 创建 / 更新时间。

后续允许一条资料同时拥有正文和多个附件。不要把“资料”等同于“文件”。

---

## 三、公共模板 / 规则层

公共模板层不是第三个一级模块。它服务于客户管理，用于减少重复配置并保持结构一致。

主要包括：

- 业务模板；
- 业务属性模板；
- 缴费模板；
- 客户属性模板；
- 产品定义；
- 分类与标签。

### 模板原则

> 模板决定结构，不拥有客户数据。

模板更新必须遵循：

1. 新建客户实例默认使用最新模板；
2. 老客户实例保留已有值；
3. 新增模板字段可以为老实例增加空字段或待补充字段；
4. 删除 / 修改模板字段不得静默删除客户历史数据；
5. 如未来发生重大结构变化，应引入模板版本，而不是原地覆盖历史结构。

---

## 四、三个数据层的判断规则

开发任何新功能前，先判断数据属于哪一类：

| 数据层 | 例子 | 是否客户独立 |
| --- | --- | --- |
| 客户实例数据 | 号码、专线、联系人、合同、缴费状态 | 是 |
| 公共模板 / 规则 | 专线字段模板、缴费模板、客户属性模板 | 否 |
| 公共工作资料 | 资费、流程、操作截图、制度、模板文件 | 否 |

示例：

- “客户 A 的 100M 专线月费 1200 元” → 客户实例数据；
- “互联网专线包含带宽、月费、公网 IP 字段” → 公共业务模板；
- “2026 年山东互联网专线资费表” → 工作资料。

---

## 五、客户管理与工作资料的关联

未来客户业务可以关联工作资料，但默认只保存关联关系，不复制公共资料。

例如：

```
客户 A
└── 互联网专线 100M
    ├── 当前实例：月费、IP、合同到期日……
    └── 关联公共资料
        ├── 互联网专线产品介绍
        ├── 2026 山东专线资费
        ├── 专线开通流程
        └── CRM 操作指南
```

当公共资费或流程更新时，客户业务通过关联可以看到新版本，而无需给每个客户重新上传一份文件。

---

## 六、当前路由边界

v1.4 架构基础：

- `/work`：工作一级入口；
- `/work/customers`：客户管理工作台；
- `/customers`：客户列表；
- `/customers/{id}`：单个客户工作空间；
- `/work/library`：工作资料入口；
- `/products`、`/accounts`：旧功能暂时保留，作为过渡辅助入口；
- `/search`：工作搜索。

原 `/work?home=tasks|payment|promos|recent` 链接继续兼容，会转到 `/work/customers` 对应标签。

---

## 七、后续开发顺序

建议按以下顺序继续，避免再次出现页面先行、数据边界后补的问题：

1. 工作资料的数据模型、版本规则、附件策略；
2. 工作资料列表、详情、新建、编辑、搜索；
3. 产品定义与工作资料关联；
4. 客户业务实例与公共产品 / 资料关联；
5. 公共业务模板和业务属性模板版本化；
6. 客户属性模板及客户个性化覆盖；
7. 将旧 `/products`、`/accounts` 等能力逐步重新归位。

任何阶段都优先保证旧客户数据兼容，不做一次性大迁移。
