# 小助手收集：微信小程序

原生工程在 `miniprogram/`，AppID 为 `wxcb9395eac340e8cb`。复用青岛号码收件箱、数据库、邀请入口和去重规则。第一版手动填写号码，不调用微信登录、通讯录或获取手机号接口，不需要 AppSecret。

## 导入和预览

1. 安装微信开发者工具，以小程序管理员微信扫码登录。
2. 导入仓库的 `miniprogram` 文件夹，核对 AppID，使用普通小程序模式。
3. 在微信公众平台的小程序后台，将 `https://jituan.zbassistant.site` 配置为 request 合法域名。保持工具里的域名校验开启。
4. 在现有助手后台复制号码收集链接，在小程序“设置收集入口”中粘贴完整链接或入口码，保存。请勿将真实入口码写入源代码、测试或公开审核材料。
5. 勾选授权说明，填写号码后提交。结果只显示本次新增和重复数量，不展示待录名单。管理员在现有号码收件箱中处理。
6. 使用工具的“预览”扫码真机测试，再上传代码。备案审核与代码审核是两个流程；通过所需审核后，在公众平台发布。

## 验收清单

- 单个、多个号码提交；同一批重复与网页已提交号码重复。
- 未勾选授权、空号码、错误号码、超过100行的限制。
- 网络断开后内容保留，恢复后可重新提交；连续点击只发一次请求。
- 失效或轮换后的入口码不可提交，替换入口后恢复。
- 从分享卡片打开直接进入同一收集入口；分享卡片携带入口权限，只转给获准人员。
- 清除入口后，本机不再记住入口码；结果页不展示其他人的号码。
- 原网页和 Windows 收件箱继续工作，管理员能收到新提交。

自动化已覆盖服务端接口及微信 API mock 下的页面控制逻辑。自动化不能替代开发者工具编译、真机预览和平台审核。

## 后端发布与网络

新增 `POST /number-submit/mini/submit`，Authorization 使用 Bearer 入口码。JSON 为 `numbers` 字符串数组和 `consent: true`。最多100个非空号码、32KiB请求体；整批先校验再写入。返回仅包含 `ok/received/added/duplicates`。

API 沿用现有 `/number-submit/*` 公共路径，当前青岛 Caddy 放行规则已覆盖，不需要新增端口、改 DNS 或暴露管理后台。候选后端版本1.7.19须实际部署后再联调。未经授权的请求应返回401；不得用真实号码做无人值守生产测试。

入口码是有权限的邀请凭证，不是 AppSecret。小程序会本地保存入口码，分享时附带入口码；后台轮换现有网页收集入口将同时令旧网页链接和旧小程序入口失效。小程序没有名单查询接口，已有网页待录页行为保持。
