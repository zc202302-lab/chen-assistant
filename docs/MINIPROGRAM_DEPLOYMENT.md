# 小助手收集：微信小程序

原生工程为 miniprogram/，AppID wxcb9395eac340e8cb。复用现有号码收集服务、邀请和去重规则，手动填写最多100个号码。无微信登录、通讯录或绑定手机号读取，不需要将AppSecret放入客户端。

## 管理员首次预览与分享

1. 导入当前PR候选的 miniprogram 文件夹，核对AppID。
2. 开发者工具新建自定义编译模式，启动页面 pages/index/index，启动参数填写 invite=<现有网页收集链接最后一段入口码>。只在本地设置，不提交 project.private.config.json 或真实入口码。
3. 按该模式编译并预览，确认识别入口后，用微信菜单转发这个小程序给填写者；分享路径会自动携带 invite 参数。接收者直接填写号码，无需输入链接、入口码或做任何配置。
4. 若使用平台生成的小程序码，页面为 pages/index/index，scene 使用入口码；代码同时兼容 invite= 前缀。平台对scene有长度限制，生成时须按实际凭证长度校验，不截断。当前仓库没有小程序码生成服务，不能把普通无参预览二维码当作已绑定邀请的小程序码。
5. 无参数但曾打开有效邀请时自动恢复；有新邀请时替换；明确无效的新邀请不沿用旧缓存。首次无参数进入只提示从收集人分享的小程序卡片或二维码进入，不能提交。

## 微信后台与发布

request 合法域名配置 https://jituan.zbassistant.site，保持域名校验开启。公众平台如实完成运营主体、类目、备案及用户隐私保护指引。提交前保留程序内说明同意和微信统一隐私授权；取消授权不提交，输入保留。

管理员完成真机预览、上传、代码审核及发布。备案通过不等于代码已发布。本次未实际生成平台小程序码、上传、审核或发布。审核入口通过平台指定渠道提供测试邀请，之后轮换；不公开生产凭证。

## 验证边界

自动化覆盖真实控制器的分享参数传递、scene解析、入口缓存/轮换、热启动切换、无效邀请隔离、缺失邀请不请求、隐私取消、重复点击、失败保留、提交结果与启动导入。Node/VM不替代微信编译、原生渲染及真机分享验收。

后端保持 POST /number-submit/mini/submit Bearer 接口，无小程序名单查询接口；原网页及Windows收件箱保持。网页邀请轮换后旧网页和小程序邀请都应失效。小程序分享包含邀请凭证，请只发给需要填写的人。
